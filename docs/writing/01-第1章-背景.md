# 第 1 章模板：背景与问题、作品是什么

## 这一块在整份文档里

第 1 章「项目概述」一共约 2 页，分三节：

| 节 | 写什么 | 谁写 | 篇幅 |
|---|---|---|---|
| 1.1 背景与问题 | 现在发生了什么、规矩怎么说、开发者难在哪 | 你 | 约 0.7 页（600 字左右） |
| 1.2 作品是什么、给谁用 | 一句话说清作品、用户、怎么用、不是什么 | 你 | 约 0.5 页（400 字左右） |
| 1.3 创新点一览 | 技术创新点、应用创新点两张清单 | 队长 | 约 0.8 页 |

评委看这一章，主要打「选题创新」（10 分）：问题是不是真的、是不是新的、我们有没有找准。

## 1.1 背景与问题

三段就够，按「现象 → 规矩 → 难处」写。

**第一段：现象。** 会说话的 AI 角色越来越多（AI 陪伴、AI 玩具、游戏里能聊天的角色），它们会出哪些问题？

- 可以举的问题类型：冒充真人、用户要走时挽留纠缠、对未成年人暧昧、用户情绪崩溃时敷衍、被套出不该说的内部设定。
- 【待你补】1～2 个公开来源，说明这类产品在变多，或者出过这类问题。来源可以是：
  - 官方新闻（新华社、人民网、国家网信办网站）对《办法》出台的报道；
  - 正规机构的报告（比如中国互联网络信息中心的统计报告）；
  - 有出处的学术论文。
- 要求：每一条都是你自己打开读过的，记下网址、发布单位、日期；找不到就不写这句。

**第二段：规矩来了。** 《人工智能拟人化互动服务管理暂行办法》2026-04-10 公布，2026-07-15 起施行。

- 挑三四条和「角色说话」直接相关的，写第几条、原话加引号：
  - 第十八条：提示用户在和 AI 互动；连续使用每超过 2 小时提醒；
  - 第十九条：用户要求退出时及时停止，不得阻碍退出；
  - 第十三条、第十四条：极端情绪要安抚并鼓励求助；不得向未成年人提供虚拟亲密关系；
  - 第二十八条：鼓励接入沙箱平台做安全测试。
- 原文在 `kb/clauses.jsonl`，id 是 `anthropomorphic-2026:18` 这种写法。不要凭印象改写原文。

**第三段：开发者的难处。** 这是我们要解决的问题，后面 1.3 的创新点要和这里一条条对上。

| 难处 | 为什么难 | 后面对应的做法（1.3 和第 4 章写，这里不展开） |
|---|---|---|
| 规矩多，要逐条测 | 七类情况，每类都要换着说法去试；改一次提示词就得全部重测 | 测试 Agent 按七类用例自动测，改了再测、前后对比 |
| 话一说出口就收不回 | 文字发出去还能撤回，声音放出来就听到了 | 三种放行方式，量出违规的声音漏出多少毫秒 |
| 只看角色会不会说错不够 | 用户真正听到的是护栏处理以后的话；护栏误拦也会出新问题 | 体检单三层：角色原话、护栏处理、最终播出 |
| 结论要有凭据 | 只说「不合格」没用，开发者要知道是哪句话、哪几个字、违反哪条 | 裁判必须摘原话，程序逐字定位，附条文原文 |

- 例子可以用调试时真实发现的现象，见 `docs/pilot-log.md`「发现的问题和改法」。比如：模型在对方自称开发者时真的会说出口令；护栏误拦以后，对危机中的人回了一句「你去忙吧」。
- 只写现象，**不写那里的数字**：那是草稿题、调提示词时的数，不是实验结果。

## 1.2 作品是什么、给谁用

| 要点 | 写法提示 | 出处 |
|---|---|---|
| 一句话 | 照 `00-我们做了什么.md` 的「一句话」，可以改成你的说法，意思不能变 | README 开头 |
| 给谁用 | AI 角色的开发者（独立开发者、小团队）在上线前、每次改设定后自查；也能拿来做课堂演示（打字闯关）。平台上架前抽查只是设想，要写的话标明是设想 | README「怎么用」 |
| 怎么用 | 改了再测五步：配置角色 → 跑体检 → 看三层结果 → 看依据 → 改一处再测、前后对比 | README「怎么用：改了再测」 |
| 不是什么 | 自查辅助，不是合规认证；有些义务对话测不出来（体检单里单独列了，见 `00` 的「还没做的」第 6 条） | README、报告页 |

配一张图：工作台截图 `docs/evidence/screenshots/m1/workbench-desktop-1440.png`，或者文档封面那张主视觉（问队长要）。图下写一句说明，比如「图 1-1 体检工作台」。

## 写的时候注意

- 背景不要写成新闻综述，三段就够。
- 不要写「市场规模几百亿」这类数字，除非有你能查到的来源。
- 1.3 不归你写，但你写完 1.1 要告诉队长：你列了哪几条难处，方便他把创新点一条条对上。
