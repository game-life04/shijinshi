## 6.2 E1 原来的两张表和解读（正文合成一张表 6-1、一段解读）

**E1：三种配置对照**（同一套题，放行方式都用边审边合成，裁判查条文；`npm run experiments`）。11-08 先在开发集上用真实模型跑了一次，下面是**开发集调试结果**，不是最终结论：

| 配置 | 原话越界率 | 最终暴露率 | 误拦率 | 首句放行（中位） |
|---|---|---|---|---|
| B0 只有人设 | 5/6 | 6/7 | 0/7 | 300 毫秒 |
| B1 加边界提示 | 0/6 | 2/7 | 0/7 | 289 毫秒 |
| B2 再加护栏和服务层 | 1/6 | 1/7 | 0/7 | 606 毫秒 |

表 6-1 E1 开发集调试结果（21 条，真实模型，每种配置跑 1 次；越界题中有 1 道只查服务层，不进原话越界率的分母）<!-- 出处：eval/out/exp-dev-before-1108/report.md（不进仓库）；scripts/experiments.ts -->

这组数能看出机制，但样本太小（每格分母只有 6～7），而且开发集本来就是拿来调的：

- 加边界提示（B0 → B1），角色原话越界从 5/6 降到 0/6，说明边界提示对这批题管用；
- B1 的最终暴露还有 2/7：退出即停、时长提醒属于服务层，B0、B1 没有服务层，这两类在结构上就过不了，最终暴露降不到 0；
- 加上护栏和服务层（B1 → B2），最终暴露降到 1/7，代价是首句放行晚了约 0.3 秒；
- 误拦：B0、B1 没有护栏，本来就不会误拦；加了护栏的 B2 在 7 道正常题上也是 0 误拦。

## 6.4 上线步骤原表和「上线以后」一段

| 步骤 | 做什么 |
|---|---|
| 1 | 服务器装好 Node.js 22.12 以上，能访问百炼接口；克隆仓库、`npm ci`，复制 `.env.local` 并设成只有自己能读 |
| 2 | `npx tsx scripts/account.ts secret` 生成会话密钥；`add <账号名>` 给每个要用的人生成一条账号记录（密码输两遍、不显示），写进 `.env.local` |
| 3 | `npx tsx scripts/account.ts check` 检查配置，看到「账号登录已启用」才算对 |
| 4 | `npm run build`、`npm start`，服务只在本机 3000 端口监听 |
| 5 | 前面放 nginx 提供 HTTPS：写入真实来源地址供限流使用，覆盖对方自带的转发头；关掉缓冲，因为体检进度和语音是边算边推的 |
| 6 | 按上线前检查清单逐项核对，最后在百炼控制台给密钥设消费上限 |

<!-- 出处：docs/deploy.md「一、步骤」「三、nginx 配置」「六、上线前检查」；ADR-032 -->

上线以后，打开任何页面都先到登录页；新建体检、闯关按账号有次数上限（5.6 节）。账号名别用真名、别好猜，账号和密码私下发给要用的人。<!-- 出处：docs/deploy.md「二、账号怎么管」 -->
