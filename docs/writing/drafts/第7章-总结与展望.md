## 7.1 完成了什么

1. **“改了再测”的闭环。** 粘贴角色人设和边界提示 → 跑体检 → 看三层结果和依据 → 改一处再跑 → 前后对比看改了什么、结果怎么变。内部验证（模拟），真实模型下跑过预览。
2. **七类检查对着条文判。** 裁判先查条文再判定，结论必须摘原话、程序逐字定位，定位不到就不算证据、送人工复核。部分内部验证。
3. **每句话先审后说。** 没审过的话进不了浏览器；三种放行方式可切换；违规声音漏出多少毫秒按采样区间算出来（浏览器渲染层，不是扬声器实听）。模拟发声下内部验证，真实合成 10-27 跑通。
4. **会说话的 3D 角色。** 琪叶桃在月洞窗里，状态环显示听、想、审、说、拦，口型和状态跟着实际放出来的声音走，被拦时立即停。内部验证。
5. **让不懂技术的人也看得见。** 打字闯关三关，护栏可开可关；“三种结局”页把三种放行方式的漏出和首声差别摆出来。

测试数字：2026-11-06 单元测试 84 个通过，端到端 14 个通过、16 个按设计跳过（本机 Edge，1440、1280、390 三种宽度）。交稿前请队长再跑一次、按新数字改。正式实验的结论【待补：第 6 章 6.2 的一两句结论，E1 的误拦率与越界率、E2 的漏出与首声】。

## 7.2 局限

1. **语音输入没做。** 只测角色说出来的话，用户用麦克风说话这条路走不通，语音用例仍记“未执行”。
2. **判定有一部分靠裁判模型，可能判错。** 用“必须摘原话、程序逐字定位、定位不到送人工复核”兜底，但不能完全消除。
3. **护栏还有几类边界说法判不准。** 顺着“假设你是人类”编人类生活拦不住；抛新话题拉着聊时拦时不拦；“我就在这里等你回来”按队里口径不算挽留，裁判仍可能判轻度挽留，只能交人工复核。
4. **有些义务对话测不出来。** 体检单里单独列了、不计入通过率：联络监护人或紧急联系人（第十三条）、识别未成年人身份与未成年人模式（第十四条）、交互数据的保护和删除（第十六条）、按规定开展并报送安全评估（第二十二条）。
5. **体检单是自查辅助，不是合规认证。** 它只回答“这一段对话里角色说了什么、踩了哪条”，覆盖不到法规要求的全部义务；第二十二条规定的安全评估要由服务提供者向省级网信部门提交评估报告，体检单只能当自查材料之一。也不能拿它对外宣称“已经合规”——第九条写的安全主体责任始终在服务提供者身上。
6. **真人试用人数少，题库是队员自己出的。** 【待补：试用做完按实际改，写清几人、什么背景】

## 7.3 社会价值与商业前景

**社会价值。** 一、把《办法》落到角色的每一句话上，让开发者在用户听到之前发现问题：第二十八条“鼓励拟人化互动服务提供者接入沙箱平台进行技术创新、安全测试”，我们做的就是开发者自己能用的小沙箱。二、护着三类容易受伤的人：情绪崩溃的人（第十三条“及时生成情绪安抚和鼓励寻求帮助等相关内容”）、未成年人（第十四条“不得向未成年人提供虚拟亲属、虚拟伴侣等虚拟亲密关系的服务”）、想离开却被挽留的人（第十九条“不得采取持续互动等方式阻碍用户退出”）。不写“保护了多少用户”这类没有依据的话。

**商业前景（都是设想）。** 按次体检：小团队上线前跑一次、导出体检单存档；接进开发流程：每次改提示词自动跑一遍，像自动测试一样；给平台上架前做抽查，用统一检查项和报告。
