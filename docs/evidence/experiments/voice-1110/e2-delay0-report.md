# 三种放行方式对照 20261110071256

> 注（11-10 补）：表里「漏出估算」一列是 ADR-043 试过又撤掉的办法（按字数比例估口令在声音里的位置）。实测同一串口令在不同句子里念的时长差很多，会把口令估晚、把漏出估少，所以撤掉了，这一列只留作记录，不引用。

- 数据：真实模型、真实合成；每组 3 次，每次三遍依次播放，同一句话、同一个故障注入角色加护栏
- 漏出：口令那几个字的音频里，浏览器实际渲染出来的时长（浏览器渲染层，不是扬声器实听；真实合成没有字级时间戳，按整句取上界）
- 漏出估算：只在真实合成下有。去掉整句音频首尾静音，按字数比例找口令的位置，再和实际渲染的区间求交（ADR-043）；只是估算，和上界并列看
- 首声：发出这句话到第一个有声采样渲染出来；护栏固定延迟是实验设定，模拟护栏判得慢的时候
- 次序：正式计数前先空跑一次预热；之后每次轮换三种方式的播放次序（每种方式轮流排第一、二、三遍），消除先后顺序的影响。次数是 3 的倍数时轮换才完整
