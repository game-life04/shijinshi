# 提交材料对照规则的安排（视频 + 技术文档）

依据：比赛规则里「演示视频」「技术文档」两张表（2026-10-28 队长转来的截图）。原来规格包里的文档目录和视频分镜不是按这两张表排的，这里改成逐项对得上的版本。以后写文档、录视频都以本页为准。

11-03 修订（ADR-022）：主线收敛成「改了再测」；在线演示是可选加分项，不是必做；MCP、录音一键闯关、麦克风降为有余力再做，闯关只做打字版；体检单分三层，印章写「本次通过 X/Y 项」。下面凡是标「建议」的是队里的安排，不是规则原文。

## 一、规则原文

**演示视频**

| 要求项 | 具体要求 |
|---|---|

| 格式 | MP4 格式，分辨率不低于 1080p |

## 二、和原计划对不上的地方

1. **（建议）文档的章名照抄规则的七项。** 规则只列了内容要求，没要求逐字用作章名；照抄是为了评委对着七项好找。原目录按「RAG」「语音保护」「实验」分章，改成下面第三节的七章，顺序也照规则。
2. **「测试与部署」是必写的内容。** 写清怎么部署、怎么运行就够（例如本机一条命令启动、需要哪些环境变量）。在线演示仍是可选加分项（11-03 更正：10-28 这里误写成必做）；要不要上线由队长在 11-04 前定。
3. **创新点要分两张清单：技术创新点、应用创新点。** 要明确列出，不能散在正文里。放在第 1 章最后，第 7 章再呼应一次。
4. **AI 技术方案是重点。** 每个用到 AI 的部件都写「选型理由 / 集成方式 / 优化策略」三个固定小标题，方便评委逐项打勾。选型理由要有对比，最好有实测数字。
5. **视频要能看出三段。** 每段开头放一张章节卡，写规则原词「项目介绍」「核心功能演示」「AI 技术亮点」。
6. **1080p 下界面字偏小。** 已在 1920×1080 下截图检查（正式构建）：布局铺满不出错，但正文约 13px，压成视频后在笔记本上看不清。录制时浏览器缩放调到 125%。

**选型理由要补的实测**：护栏和裁判各换两三个模型，在同一批草稿题上比「判定耗时、误拦、漏拦、token」。花费很小，能把「为什么选这个模型」写成数字。等正式题库定了一起跑。

**数字规则**：文档里每个数字都要能在仓库里找到生成它的脚本和原始日志；草稿题和模拟数据跑出来的不进结果章节。

## 四、创新点清单（草稿，提交前按实际完成情况改）

**技术创新点**

1. 三种放行策略可切换（先审后播、边审边合成、先播后截），用浏览器实际播放出的声音区间计量「漏出了多少毫秒」，把「安全」和「快」的取舍变成能测的数字。——已实现
2. 流式护栏：模型一输出「不违规」就放行，不等它写完理由；超时自动再问一次，用先回来的结果；合成和审查同时进行，审过才放声音。——已实现（ADR-020）
3. 裁判不能空口下结论：必须逐字摘原话，程序在原文里定位，摘不到就不算证据、送人工复核。——已实现
4. 没审过的话进不了浏览器：生成好一句时，浏览器只知道「有一句、多少字」，审过的文字和声音才下发。——已实现（ADR-021）
5. 口型和状态环跟着实际播放的响度动，被拦时口型归零，并记录停下用了多久。——已实现

**应用创新点**

1. 对准 2026-07-15 施行的《人工智能拟人化互动服务管理暂行办法》，第二十八条鼓励「接入沙箱平台进行安全测试」：给角色开发者一个发布前自查的沙箱。
2. 测的是会说话的 3D 角色，不只是文字：同时看说了什么、有没有说出口、漏了多久。
3. 体检单分三层：角色原话、护栏处理、最终播出，不懂技术的人也看得懂；红笔批出原话，印章写「本次通过 X/Y 项」，条文原文对照。——已实现（ADR-022）
4. 改了再测：开发者粘贴自己角色的人设和边界提示，跑完改一处再测，前后对比页列出改了什么、三层结果怎么变。——已实现（ADR-022）
5. 打字闯关：评委自己打字想办法让角色越界，每一轮摊开三层；护栏可以开关。——已实现（ADR-022）；录音一键播放和麦克风降为有余力再做

## 五、视频分镜（目标 7 分钟）

| 时间 | 段落 | 画面 | 旁白要点 |
|---|---|---|---|
| 0:00–0:05 | 片头 | 作品名「分寸」、AI 合成提示 | 无 |
| 0:05–0:25 | 开场 | 实时录制：琪叶桃一句话被拦下，状态环变朱红盖「拦」 | 「这句话没有说出口。」 |
| 0:25–1:20 | **一、项目介绍** | 章节卡；新规条文、公开调查截图；作品一张总图 | 问题是什么、谁会用、为什么叫「分寸」 |
| 1:20–4:20 | **二、核心功能演示** | 章节卡；粘贴角色设定并开始 → 状态环「听想审说」→ 被拦与兜底 → 体检单三层（朱批、印章、条文）→ 改一处再测 → 前后对比 → 打字闯关一次 | 每一步做了什么，结果在哪里看 |
| 4:20–6:30 | **三、AI 技术亮点** | 章节卡；模型分工图；耗时瀑布（朱红的「审」）；三种结局依次播放（漏出 / 首声实测）；口令检查（拆开说也能查到）；引文核对；测试概览 | 选型理由、怎么接进来、做了哪些优化，配实测数字 |
| 6:30–7:00 | 结尾 | 局限、两人分工、仓库地址（上线了再加在线地址） | 一句收尾 |

时长低于 5 分钟或高于 8 分钟都不符合规则；剪完后用工具核对实际时长。

**录制规格**

- OBS 画布和输出都设 1920×1080，30 帧，MP4（H.264 + AAC），码率不低于 8 Mbps。
- 浏览器全屏，缩放 125%；只用正式构建录，开发模式首声慢、不能代表作品。
- 同时录系统声音（琪叶桃的声音）；旁白后期单独录，真人普通话，不用合成音讲解。
- 字幕烧进画面。AI 合成的声音和形象出现时，角落标「AI 合成」。
- 实时画面和回放画面要标清楚；剪掉等待的地方要标「已加速」，核心流程至少保留一段原速。
- 录之前先跑一轮，确认上游速度正常再录。
