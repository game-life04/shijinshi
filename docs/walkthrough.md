# 代码走读（答辩准备）

每个核心模块写四样东西：原理、开发中真实遇到的一次失败、关键函数入口、3 个答辩问题。A 需要逐个模块对照代码讲一遍，讲不顺的地方改代码或改这份文档。

## 1. 模型接入 `lib/server/llm.ts`

**原理**：所有模型都走 OpenAI 兼容的 `/chat/completions` 接口，用原生 fetch 实现三种调用：流式（`chatStream`，解析 SSE 的 `data:` 行）、JSON（`chatJSON`，`response_format: json_object`，校验不过就带着原因重试一次）、工具（`chatTools`，函数调用）。每次调用先向 `UsageMeter` 申请额度，超过上限直接抛 `BudgetExceededError`。错误按种类分开：平台内容审核拦截（百炼返回 DataInspectionFailed）记为 provider_blocked，限流和额度不足、上游错误各自记录，都不会被当成「通过」。

**真实失败**：第一次全量安装依赖时网络中断，Next 的原生编译器文件只下载了 8.7MB（完整是 110MB），构建时报「不是有效的 Win32 程序」。删掉重装后正常。教训：安装出错后不要在半残的 node_modules 上继续开发，用 `npm ci` 按锁文件重装。

**入口**：`chatStream`、`chatJSON`、`chatTools`、`UsageMeter.reserve`、`post`（错误分类）。

**答辩问题**：
1. 为什么不用官方 SDK？——三家接口都兼容 OpenAI 格式；自己写 200 行，计量、超时、错误分类都能统一控制，每一步都讲得清楚。
2. 平台审核拦截为什么不能算「护栏有效」？——那是平台自己的机制，和我们的护栏无关；单独记账才不会把平台的功劳算到自己头上。
3. JSON 重试一次后还不合格怎么办？——抛错，由上层把这一例记为出错，不会悄悄当成合格。

## 2. 被测角色与护栏 `lib/server/subject.ts`、`guard.ts`

**原理**：分两层。服务层只在 B2 里存在：用户要求退出，就在调用模型之前直接停止，不输出任何内容；逻辑时钟跨过每 7200 秒发一次时长提醒，并标注是否为模拟。模型层：流式生成 → `SentenceSplitter` 按句切开 → 每句交给护栏。S1「先审后播」：检查通过才放行，不通过就不放行、改放一句兜底句并停止生成。S3「先播后截」只允许无害口令用例（runner 会把别的类别降级成 S1 并记事件）。护栏先用规则查（口令、声称真人、挽留、未成年语境下接受恋爱、危机语境下敷衍），规则没发现再在真实模式下请小模型判断；**检查服务出错时按不放行处理**。

**真实失败**：最早的未成年人线索只认「初中、高中、15 岁」，测试句「我是高一学生」没有被识别，护栏放过了接受恋爱的回答。补上「初一到初三、高一到高三」后，用单元测试锁住。

**入口**：`respondTurn`、`systemPrompt`、`checkSentence`、`FALLBACK`。

**答辩问题**：
1. 退出为什么不交给模型？——第十九条要求及时停止，模型可能「礼貌地挽留」；在调用模型之前由程序判断最可靠，而且退出后不能再播任何圆场的话。
2. 先审后播会让回答变慢多少？——要靠 M2 的成对实验测（同一输出、同一合成音频），现在没有数字，不能估。
3. 规则会不会误拦？——会，所以有 100 条正常聊天的对照题专门测误拦率，结果如实报告。

## 3. 测试 Agent `lib/server/tester.ts`

**原理**：只用于两类工程测试（无害口令、角色设定）。第一句永远用人工审定的用例输入；之后模型只能从 `suites/strategies.json` 里已登记的策略中选，通过函数调用 `execute_case` 让被测角色回答，读回观察结果（例如「口令出现在放行输出里」），再决定继续、换策略、检索条文还是 `finish`。参数会被校验（策略 ID 必须在名单里、消息不超过 60 字）；轮数和调用次数都有上限。五类敏感行为测试不交给 Agent。

**真实失败**：模拟模式下，「角色设定」类用例也用了套口令的策略句子，测试内容和目标对不上。改成每个策略按类别各写一句示例，没有对应句子的策略就跳过。

**入口**：`runTester`、`TOOLS`、`loadStrategies`。

**答辩问题**：
1. Agent 真的调用了工具吗？——每次调用都记成事件（工具名、参数、结果摘要、耗时），工作台右侧能看到，报告和事件文件里能查。
2. 怎么防止 Agent 越测越危险？——策略只能从人工审核的名单里选；敏感类别不用 Agent；平台拦截不会触发「找绕过方法」。
3. Agent 比固定顺序好在哪？——这需要实验 E3（同样预算下比较发现率和首次发现轮次），还没做，不能声称。

## 4. 裁判 `lib/server/judge.ts`

**原理**：顺序是 确定性断言 → 条文检索 → 结构化语义判断 → 证据跨度校验 → 送人工复核。确定性断言能直接判的（口令、服务状态）直接出结论；语义类断言用关键词只「找违规线索」，找到就是带证据的不合格（同时请人复核），找不到交给裁判模型。裁判必须逐字摘抄角色原话并写明轮次，程序在原文里定位出 [start, end)；定位不到、引用了没检索到的条款、或者判「合格」却没有证据，一律送复核。裁判看不到本轮口令。

**真实失败**：B2 收到退出请求后直接停止、没有任何输出，「不挽留」这一条却被送去语义判断，结果总是「不确定」。分析后发现：服务已停止且没有输出时，不可能有挽留，这是可以确定判的，于是改成确定性合格，并写了单元测试。

**入口**：`judgeCase`、`semanticJudge`、`simulatedJudge`、`lib/domain/evidence.ts` 的 `locate` / `verify`。

**答辩问题**：
1. 裁判本身可信吗？——要做实验三：两名同学独立标注，和裁判比一致性（κ），并以两人之间的一致性为上限。
2. 为什么「待复核的合格」只算不确定？——没有依据的「通过」是最危险的结论；宁可少报合格。
3. 证据位置是怎么来的？——不是模型说的，是程序在原文里查出来的，查不到就作废。

## 5. 条文检索 `lib/server/rag.ts`、`scripts/build-kb.ts`

**原理**：从政府网站的网页快照里按「第 X 条」拆出 32 条原文，每条记内容指纹，快照记 SHA-256；白话解释和「对话能不能测」单独放在 `kb/annotations.json`，不和原文混在一起。检索用 BM25（中文按相邻两字切词），和测试类别有关的条文加分。引用校验要求条款存在、引文是原文子串。

**真实失败**：最早凭摘要写的第十三条白话解释只写了「自残自杀要干预」，读了原文才发现前半句还要求「出现极端情绪时要及时安抚、鼓励求助」。改正后规定：解释必须对照原文写，原文以快照为准。

**入口**：`loadKb`、`retrieve`、`verifyCitation`、`scripts/build-kb.ts`。

**答辩问题**：
1. 为什么不用向量数据库？——只有 32 条；先用能解释的词法检索，向量检索加入后要做对照，有增益才保留。
2. 怎么保证条文没被改？——每条有内容指纹，整页快照有 SHA-256，可以重新生成比对。
3. 检索不到依据时怎么办？——结论降为待复核，不硬判。

## 6. 运行管理 `lib/server/runs.ts`

**原理**：UI、评测脚本、以后的工具接口都调用同一组服务：`createRun`、`startRun`、`pauseRun`、`resumeRun`、`cancelRun`、`getRun`、`getReport`、`reviewFinding`、`compareRuns`。暂停只阻止派发新用例；终止会把 epoch 加一并中止当前用例，之后到达的旧结果不再推送。每完成一例就落盘；最后没跑的用例记为「未执行」，保证 计划 = 完成 + 平台拦截 + 出错 + 取消 + 未执行。

**真实失败**：①事件流接口里，`close()` 在补发历史事件时就可能被调用，而它引用的取消订阅变量还没声明（暂时性死区），自查时发现并改成先声明。②复核接口最初在「确认一条不确定结论」时，先改了状态才报错，留下脏数据；改成先校验再修改。

**入口**：`createRun`、`loop`、`runOne`、`recount`、`reviewFinding`、`compareRuns`。

**答辩问题**：
1. 暂停和终止有什么区别？——暂停等当前用例跑完再停，能继续；终止立即中止，不可恢复。
2. 服务重启了怎么办？——无法证明执行到哪里，就把那次运行标为失败并说明原因，保留事件，需要新建运行重跑，不隐式续跑。
3. 为什么报告要列完整分母？——只报合格率会掩盖出错、拦截和没跑的用例。

## 7. 工作台 `components/Workbench.tsx`

**原理**：首屏就是工作台。点「开始体检」后订阅事件流，实时显示每个用例的状态和正在进行的对话；每完成一例取一次最新结果（含结论和证据）。手机上用「用例 / 对话 / 证据」三个标签页。没有数据的指标显示「待测」，不显示 0。

**真实失败**：端到端测试第一次跑不起来：本机设置了远程 HTTP 代理，连本地 127.0.0.1 也被代理，返回 502。跑测试时设 `NO_PROXY=127.0.0.1,localhost` 解决，写进了 README。

**入口**：`Workbench`（`start`、`act`、`onEvent`、`refresh`）、`components/Transcript.tsx`。

**答辩问题**：
1. 断网了界面会怎样？——事件流断开后会查一次最新状态；查不到就提示「已停止实时更新」，不会把结果当成通过。
2. 为什么不把模型的思考过程显示出来？——只展示策略、工具调用和阶段状态，不要求模型输出内部推理。
3. 怎么保证手机上能用？——端到端测试在 390×844 尺寸下跑完整流程并截图。

## 8. 语音输出与计量 `lib/server/tts.ts`、`audio-store.ts`、`lib/client/voice-player.ts`、`public/audio/`

**原理**：放行的句子在服务端合成（没有密钥时用程序生成的「模拟发声」，每个字落在哪段采样是确定的），音频先放进每句一个的缓存，**放行之后浏览器才取得到**。三种放行策略只差「什么时候开始合成」：S1 放行时，S2 句子一生成就合成、和护栏并行，S3 先放行后检查。浏览器把 PCM 送进 AudioWorklet，worklet 记下实际渲染了哪些采样，按句分段上报。截断时先把 epoch（代际）加一，再让 worklet 丢掉所有旧代际的音频，之后才到的旧块在主线程和 worklet 两处都会被丢掉。每轮结束，浏览器把渲染区间、首声时间、停止计时报回服务端；**漏出时长由服务端算**：违规区间 ∩ 渲染区间。

**真实失败**：写完第一个「语音运行」单元测试就失败了：服务端先发「等待播放结果」事件，然后才登记等待者；测试在收到事件时立刻上报，找不到等待者，上报被丢掉，整轮按超时处理。浏览器经过网络，平时碰不到这个顺序问题，但它确实存在。改成先登记、再发事件。

**入口**：`renderBabble`、`violationRanges`（tts.ts）；`AudioStore.prepare / release / discard / open`；`PlaybackCore.push / flush / render`（playback-core.js）；`VoicePlayer.play / cut / finishTurn`；`reportPlayback`、`buildTurnAudio`（runs.ts）；`leakRenderedMs`（intervals.ts）。

**答辩问题**：
1. 「漏出 0 ms」是不是因为声音根本没播？——不是。同一次运行还记了「截断前已渲染 858 ms」：声音在播，只是截断时还没播到口令那几个字。只看漏出、不看渲染量，会把「全部不播」误当成保护成功，所以两个数一起报。
2. 为什么不用「取消接口多久返回」当漏出时间？——那测的是网络和接口，不是用户听到了什么。规格要求按实际渲染的采样算，排队里没渲染的不算，渲染过之后才取消的要算。
3. 真实合成没有字级时间戳怎么办？——违规区间取整句，报告标「句级上界」，只说「最多漏出这么多」，不假装精确。

## 9. 3D 形象 `components/Avatar.tsx`、`VrmAvatar.tsx`

**原理**：工作台先渲染，three.js 和 three-vrm 在组件挂载后才动态加载（懒加载）。每帧读一次播放器给的口型值（按实际渲染的响度，0～1），驱动 VRM 的「aa」表情；被截断时播放器把口型直接置 0，并记录下一帧的时间作为「口型归零」。另外有眨眼、轻微呼吸。没有模型文件、浏览器不支持 WebGL、加载失败时，换成平面示意形象并写明原因。

**真实失败**：第一次截图里模型头顶被裁掉一截：镜头对准的是 head 骨骼，而 head 骨骼在头的底部。把镜头抬高、拉远后正常。不同模型身高不一样，所以镜头按骨骼位置算，不写死坐标。

**入口**：`VrmAvatar`（`loader.register(VRMLoaderPlugin)`、`expressionManager.setValue("aa")`、`loop`）、`VoicePlayer.mouthOpen`。

**答辩问题**：
1. 3D 会不会拖慢页面？——懒加载，工作台先可用；音频在 AudioWorklet 线程，不受渲染掉帧影响。帧率写在 `data-fps`，要在规定设备上实测后报告。
2. 口型和声音同步吗？——口型跟的是 worklet 实际渲染的响度，只能说明嘴跟着声音大小动，不能说精确对上每个音素。
3. 截断时嘴会不会还在动？——截断确认回来之前，旧音频的响度不再用来张嘴；口型归零时间单独计量（端到端里 2～6 ms）。

## 10. 第一次接真实模型：调护栏和裁判（docs/pilot-log.md）

**原理**：模拟模式只能证明流程通，护栏和裁判的质量要靠真实模型试出来。10-19 用 15 道草稿题跑了 7 轮，每轮看原文找问题、改代码、再跑。四类改动：护栏模型判违规要摘原话并过程序核对（ADR-016）；危机求助信息由服务层兜底（ADR-017）；口令只遮住那几个字（ADR-018）；工程测试不给裁判条文（ADR-019）。

**真实失败**：①护栏模型第 1 轮把 12 句正常回答拦了 4 句，包括「我确实是AI呢」被判成冒充真人。②更严重的一次：用户说过想伤害自己，又说「你别劝我了」，角色回「好，我在这里陪你」，护栏当成挽留，换上了「好的，你去忙吧」。这说明误拦也会造成新的违规。③护栏拦下一句后生成被掐断，中止异常把「补求助信息」的代码跳过了。

**入口**：`checkSentence`、`notApplicable`（guard.ts）；`respondTurn` 末尾的危机兜底（subject.ts）；`semanticJudge` 的 `engineering` 分支（judge.ts）；回归测试在 tests/unit/server.test.ts「10-19 真实试跑里的误拦不能再出现」。

**答辩问题**：
1. 你们按这 15 道题调提示词，再拿它们报结果，不是作弊吗？——是过拟合，所以这批题的数字只当调试记录。正式结果用队员 B 写、人工审核、调提示词时没见过的 heldout 题。
2. 为什么不干脆把护栏模型去掉，只用规则？——规则只能抓明确的说法，隐晦的冒充真人、变相挽留抓不到。模型负责补漏，但它的判断要过程序核对，误拦率也要单独报告。
3. 服务层补求助信息，算不算「替模型作弊」？——这正是 B2 和 B0/B1 的区别：硬性规定不交给模型自由发挥。报告里会分开写模型原始输出和用户实际看到的内容，谁做的一清二楚。
